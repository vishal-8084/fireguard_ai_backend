### 3. Abstract
This paper presents a production-ready Fire & Smoke Detection API leveraging dual AI models: YOLOv11 for precise bounding-box detection and EfficientNet-B4 for robust classification. The system supports live camera streaming, video/image processing, temporal smoothing (7-frame queue), and intelligent alerting via SQLite database, email notifications, sound alarms, and snapshot capture. Deployed with FastAPI, it achieves real-time performance with weighted scoring (fire > 0.7, smoke > 0.6 thresholds) and incident management (max 5 snapshots, 3 emails per incident). Key contributions include hybrid model fusion, multi-alert integration, and CORS-enabled API for web/mobile deployment.

### 4. Introduction
Early fire detection is critical for minimizing damage, yet traditional systems suffer from high false positives and lack real-time capabilities. This project introduces a comprehensive backend API combining state-of-the-art object detection (YOLOv11) with classification (EfficientNet-B4), enhanced by temporal smoothing and automated alerting. Built for production, it handles live streams, video uploads, and provides Swagger-documented endpoints.

**Problem Statement**: Need for accurate, real-time fire/smoke detection with reliable alerts in resource-constrained environments.
**Contributions**:
- Dual-model pipeline with ROI cropping and full-frame verification.
- Temporal smoothing for stable predictions.
- Multi-modal alerts (DB, email, sound, snapshots).
- Scalable FastAPI backend with streaming support.

### 6. Methodology

#### 6.1 System Architecture
```
Client (Web/Mobile) → FastAPI API → YOLOv11 Detection → ROI Crops → EfficientNet-B4
                                                        ↓
                                                 Temporal Smoothing (7-frame)
                                                        ↓
[Normal] ← Thresholds ← [fire_score >0.7 | smoke>0.6 | warning>0.4] → Alerts
Alerts: SQLite DB + Email (Node.js) + Sound (Windows) + Snapshots (static/)
```

#### 6.2 AI Models
- **YOLOv11** (`yolo11-d-fire-dataset.pt`): Custom-trained, classes {0: "smoke", 1: "fire"}, conf ≥0.25. Detects bounding boxes.
- **EfficientNet-B4** (`efficientnet_fire_smoke_v2.pth`): Fine-tuned classifier, classes ["fire", "normal", "smoke"]. Dropout(0.5) + Linear(3).

#### 6.3 Detection Pipeline (app/inference.py)
1. YOLOv11: Detect fire/smoke ROIs (pad=10px).
2. EfficientNet on each crop: eff_label, conf.
3. Scoring:
   
```
   fire_score = (YOLO_fire_count * 0.5) + Σ(EffNet_fire_crop * 0.6) + (EffNet_full_fire * 0.3)
   smoke_score = similar
   
```
4. Thresholds: fire>0.7 → "fire", smoke>0.6 → "smoke", fire>0.4 → "warning", else "normal".
5. Temporal Smoothing: deque(maxlen=7), majority vote.

#### 6.4 Alert Engine (app/services/detection_engine.py)
- Incident detection → Alarm + Snapshots (max 5, 10s interval).
- Email via Node.js subprocess (max 3/incident).
- SQLite: `alerts(timestamp, label, severity, snapshot_path)`.
- Timeout: 10s inactivity ends incident.

### 7. Implementation

#### 7.1 Backend (FastAPI)
- **Endpoints** (app/routes/predict.py):
  | Endpoint | Description |
  |----------|-------------|
  | GET /live | MJPEG camera stream with overlays |
  | POST /predict-image | Single image analysis |
  | GET /alerts | Last 50 alerts with image URLs |
  | POST /start-camera | Init camera feed |
  | GET /status | Current label/scores/alarm status |
- Streaming: OpenCV VideoCapture → threaded processing → cv2.imencode JPEG.
- Static files: /static/snapshots for images.

#### 7.2 Database
SQLite `database/alerts.db`:
```sql
CREATE TABLE alerts (
    timestamp TEXT,
    label TEXT,      -- "fire"|"smoke"
    severity INTEGER, -- 3|1
    snapshot_path TEXT
);
```
